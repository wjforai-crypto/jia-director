# Jia-video

支持两条同等完整的通路。将用户输入做成可审查的视频与可继续修改的工程，口播的粗剪、精剪不能被动效创作取代。根据内容先决定观看重点与可见变化，再选工具；标题、列表、图表有明确任务时正常使用。优先复用已配置工具、项目和真实获认可案例，仅要求某个阶段时停在对应范围。

本 Skill 的制作、剪辑和修改通路均不使用 ChatCut。复用现有本地 ASR、原创词表/EDL 桥、帧级精剪、内置 image_gen、HyperFrames/GSAP 与本地合成；不因为插件已安装或历史案例成功而调用它。此约束不涉及卸载其他任务使用的插件。

新增镜头优先检索并复用现成素材；生成只解决现有素材、图片和代码不能完成的需要。按阶段读对应参考，不一次加载全部方法、上游手册或研究日志。能力范围与模块职责见 [capabilities.md](references/capabilities.md)。

## 入口

| 用户给到的输入 | 通路 | 首先读取 |
|---|---|---|
| 真人口播、访谈原片，或准备录制真人讲解的视频 | 路线一：口播视频 | [talking-head.md](references/talking-head.md) |
| 无真人出镜口播，以动画、画面、录屏、实拍素材组织表达；可含旁白、音乐或无声 | 路线二：无口播视频 | [no-talking-head.md](references/no-talking-head.md) |
| 现有工程、初稿和修改意见 | 延续已有通路和断点 | 对应通路文件及工程记录 |

按成片主线选择路线，不按是否有视频文件选择。真人讲述是主线时走口播；产品片、代码动画、科普动画、MV、画面叙事走无口播。这里“无口播”指无真人出镜口播，不等于无旁白。已有连续录屏等素材需要剪辑时，无口播路线复用原片剪辑子流程。信息可以推断时自行判断并说明，仅在结果会明显改变范围时询问。

## 人工职责与风格落位

王杰自己负责选题、核心方向与发布决定。接到用户给定选题后再研究和制作；不默认调用选题 Skill 搜热点、评分或替换题目。用户另行要求时才协助比较选题。

AI执行、AI自检、王杰人工复核分别标注，不能互相代签。按 [AI与人工分工](references/ai-human-review.md) 交接，按 [风格与生产后端](references/style-routing.md) 选风格 Skill 与渲染后端。固定已认可风格规则，不固定每期画面；新风格或大改先做代表段供人工复核。

## 开始工作

1. 从工程记录和上下文提取用途、受众、目标时长、平台/画幅、素材路径、锁定台词、风格参考、交付要求和当前授权。探测真实素材，不把链接封面当成已看过视频。保留仍有效的脚本与表达。
2. 读取 [runtime.md](references/runtime.md)，运行本包 `scripts/run-video.ps1 -Command doctor`。它读取本机运行配置；不用重新安装浏览器、模型或修改全局环境。
3. 先读已有 brief、design、分镜、合同和版本。新项目使用 `E:\视频文档\YYYY-MM-DD_项目名`；同名工程续用或建明确新版本，保留原素材和旧输出。
4. 将制作判断写入简短 brief、脚本、分镜、设计和必要的事实记录：观看位置、重点、可见变化或稳定阅读区，以及为什么切镜。这些是制作材料，不是第二套审批合同。无真实 A-roll 的新代码创作可独立渲染，不把动画粗稿冒作原片强塞核心状态。

## 两条路线的关键顺序

- **路线一：口播视频。** 目标与台词/真人录制 → 原片登记与转写校对 → 语义粗剪并导出 → 精剪原声与切点并导出底片 → 补图、MG/B-roll → 整片审片、反馈、第二稿。原片未提供时先交付录制稿与拍摄清单，不伪造已剪辑。
- **路线二：无口播视频。** 参考拆解（如有）→ 核心表达与事实 → 脚本及声音/阅读节奏 → 分镜、主体与镜头空间 → 代表段及整片预演 → 资产制作、合成与审片 → 反馈、第二稿。代码、录屏、实拍、图片及生成片段按镜头需要组合。

口播精剪前可列补图需求，不先铺入镜头迫使台词迁就它们；粗剪、精剪各自保留视频、删改理由和时间映射。参考片需要反推风格、节奏和镜头时调用已启用的 `video-recreation`，接收拆解及创作交接；它不拥有成片字幕、最终音轨或第二套时间线。未启用时按当前工具完成拆解或说明缺口，不从隔离区执行候选。

用户已批准连续执行的阶段，不反复加审批门；已有核心的人工校对、真实付费执行和用户定稿门继续遵守。粗剪后的时间码需明确是原片还是输出片，不混用。

全片使用一条明确输出时间线，指定一个字幕 owner 和一个最终音轨 owner。组件提供文字/音效候选，由 owner 统一 cue 与混音，不重复烧录字幕或叠播本人原声。改词、剪切或换配音后重建受影响的映射。

## 导演判断先于模板

代码视频、解释插入和需要重做的动效，先读 [motion-direction.md](references/motion-direction.md)。按内容选择空间层次、主次延迟、动作预判与落定、惯性/受力、光影响应和镜头跟随。它们服务注意力与因果，不是每镜必须全开的特效菜单；没有声音时按阅读和事件建立节奏，不强加BGM。

需要动作解释时，让可见变化承载信息：对象变化、操作、关系或具体行为。文字可负责命名、条件、数字、标题和必要归纳；按语义决定构图，不强制每镜贯穿同一主体、运镜、碰撞、五层或持续运动。相机为观看目的服务，数据与稳定阅读段落可以静止。

先做最能暴露风格问题的代表段，实际看动作中间帧和连续播放。关键帧漂亮、所有元素有动画、技术QA通过，都不能证明整片有镜头感。按 [motion-quality.md](references/motion-quality.md) 单独审查动作、跨镜承接和整页重置。已有连续执行授权不因外部文章建议而增加固定等待确认门。

## 制作选择

取材读 [material-library.md](references/material-library.md)：`scripts/run-video.ps1 -Command materials` 统一执行本地检索、Commons/NASA无key查询、选定下载、Mixkit指定详情页下载、来源登记、SHA去重、完整解码和静音选段。Dareful及其他正常获取的授权视频可本地导入。复用缓存也验SHA/解码，失败不只看第三方退出码；大文件留在外部库。

需要在已保存视频中找具体画面和源时段，读 [material-semantic.md](references/material-semantic.md) 使用本地VideoSeek中文检索。缺素材时仍可能误匹配，分数不是正确率，不自动采用Top1。实际查看动作与上下文、核对许可、明确源入出点后重编码，检查真实时长，再经`visual-asset-import`导入既有第03步；不自动插片、不另起字幕或音轨。laohan只参考薄供应接口，MoneyPrinterTurbo只参考缓存经验，不整套装入它们的制作流程。

每个镜头承担明确的信息或情绪任务，说明为何采用用户素材、证据、代码、图片或生成视频。代码也能组织物体、空间、镜头与可重复的运动；精确数字、标签仍用可控排版。真实产品/操作用可核验素材。MiniMax默认只用于极少数有不可替代动作或叙事价值的镜头；一张图能表达同样内容时不付费生成视频。用户明确指定其他路线时服从当前范围和预算。

用 [shot-recipes.md](references/shot-recipes.md) 从镜头任务选择少量方法。查参考时读 [motion-library.md](references/motion-library.md)：保留Emil animate原指南、LiveCanvas折线源码、awesome-opus的475条离线索引。它们是方法或参考，不能把索引条数报成可执行组件数。高级定制使用本宿主已启用或明确暴露的能力，不从隔离区加载执行。

本机外部动效库与原创作品保存入口见 [motion-archive.md](references/motion-archive.md)。先按表达任务和实际参数协议查找，原库资源不代表本人已认可。用户认可且适合复用的原创动作保存预览、源码、参数、素材及 QA；技术验证只能暂存待审。大库、依赖和媒体保留在 E 盘外部库，Skill 仅保留检索与归档规则。

连续主体、分层空间和动作响应可使用新 [镜头执行层](references/directed-runtime.md) 的 `scripts/build-directed-motion.mjs`，或直接写符合后端接口的HTML/Remotion工程。执行层是确定性的2D场景图与运动近似，不是完整物理引擎或自动电影导演。先看其当前schema和实际支持范围，不虚构资产类型或相机能力。

原有 [8类组件](references/motion-components.md) 和 [基础合成器](references/composition.md) 保留用于局部字幕、标注、证据、明确需要的图表和媒体拼接。不要把它们的整页入场顺序当成完整视频默认导演方案。透明HTML层不等于普通MP4含alpha；复杂镜头不受基础构建器配方限制。

口播逐词审片使用 [rough-review.md](references/rough-review.md)：本地转写、保守剪辑建议、原片/粗剪预览与波形联动、恢复和校字，导出同源 MP4、SRT、原片→粗剪映射。继续在 [精剪与补图面板](references/review-stages.md) 调整帧级切点、导出精剪底片，再按精剪台词选择补图、制作本地代码动效或给 Codex 派发素材任务并合成。[fine-cut.md](references/fine-cut.md) 的独立 plan/render 入口仍保留。保存不代表用户确认；校字不删录音，局部裁剪已校对句子须重新核对保留片段字幕。可选口播词表、预剪 EDL 与 video-talkcraft 接入见 [talkcraft-adapter.md](references/talkcraft-adapter.md)：原创桥保留，上游仍是独立 staged、未启用候选；不复制整个上游、不执行自动升级，也不采用其第二套时间线和字幕默认。

时间趋势折线图可按 [data-charts.md](references/data-charts.md) 使用 `scripts/render-data-chart.mjs` 和已配置的 LiveCanvas 本地运行时。它读取带来源的数据，输出可编辑工程、MP4、结果帧及回执；当前原生规格是1080×1440、30fps、3秒，横竖版需要重新构图，不能只改输出尺寸。合成数据须显式标注，真实数据需核实来源。

## 声音、生成与运行边界

- 口播默认保留本人原声。新增旁白按 [personal-voice.md](references/personal-voice.md) 使用明确本人片段与准确原话建档、逐句本地合成及识别回读；本轮采用 DotTTS SOAR 的 audio.cpp 路线，生效引擎以 doctor 当前读回为准，MOSS 仅明确选择时兼容，不自动回退。模型验通不等于本人音色或试听已确认；Huihui 仅明确的离线试读，不能冒充本人或自动进入正式声音。
- 图片优先本宿主可用的内置生成工具，当前 Codex 为 image_gen。其他宿主先确认实际图像工具；没有时继续已有素材/代码镜头，若必需生成图则说明准确缺口。指定模型时不静默替换。
- MiniMax 接入状态以 [runtime.md](references/runtime.md) 指向的实时配置及有效回执为准，自动付费默认关闭；当前任务禁止使用时不调用。服务验通、预算授权、有效载荷和项目 claim 分开核对，不能用独立脚本绕过核心合同；缺口不阻碍独立本地工作。
- 修改台词/配音后更新字幕与时间线。ASR token 区间需要校对；不要把转写当成修改稿的强制对齐，或让字卡出现在对应台词之前。
- 所有视频画面禁止制作状态标签，包括AI示意、AI情境示意、初稿、样片、未定稿；状态与生成来源记录在交付文件。合同条件、数据单位等内容本体正常呈现。构建器的可见文本校验补充人工审查，无法替代对图片里已有文字的查看。

做有声动画或切换横竖版时读取 [voice-and-timing.md](references/voice-and-timing.md)，以实际音轨规划动作与字幕，重新排构图。已有项目的尺寸、字体和声音选择继续优先。

## 验收与交付

按 [acceptance.md](references/acceptance.md) 检查最终文件；代码动效另做 [动作与叙事审查](references/motion-quality.md)。最低交付为MP4、源码与运行说明、素材来源、技术QA、实际视觉/听审范围、创作问题及修改记录；口播另保留粗剪、精剪底片和时间映射。只完成某个阶段时如实说明，技术通过与用户确认分别记录。

可用 [media-inspection.md](references/media-inspection.md) 的 `scripts/inspect-video.mjs` 从最终 MP4 解码代表帧、切点邻帧和真实尾帧，记录哈希、全量解码与声音测量；之后实际查看图像和回听。它补充核心 `qa-media`，不代替核心状态、视觉判断或用户确认。

初稿交付后承接反馈，保留版本并给第二稿；仅用户明确确认后记录定稿。不要代签认可、付费批准或发布。沿用已有核心的版本、审片、最终确认与归档接口，交付后核验归档文件可读与来源完整。
