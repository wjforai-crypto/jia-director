# 无口播制作路线：从脚本、创意或素材制作完整视频

用于没有待剪原片，或需要把脚本、创意、图片、录屏、零散视频组织成完整作品的任务。以镜头需要选择代码动效、生成视频或既有素材；一部片子可以组合这些方式。

用户只要求脚本、分镜、预演或局部镜头时，在该阶段交付，不自动扩大为完整制作或发布。具体工具、配置、调用接口和当前接入状态见 [运行说明](runtime.md)。

## 1. 建立可执行的制作输入

读取项目约定与本地配置，按运行说明检查实际能力。复用既有项目的尺寸、帧率、声音、字体、目录和版本规则；新项目建立独立目录，保留用户素材，不覆盖既有版本。

没有原片时，先在项目工程目录保存 brief、脚本、分镜和真实动画预演的工程。当前核心没有无 A-roll 的完整建项通路，可用工作区 `standaloneLocalRendering` 独立制作交付，不另建审批合同，也不把导出动画登记成真人原片。

从对话及素材提取主题、受众、观看场景、核心观点、目标时长、已有资产和限制。能推断的常规选择直接确定；只有缺失信息会改变成片目标、主要风格、成本或必须使用的声音时才提问。

建立事实与资产清单：逐条标明事实来源、用户提供素材、官方或可核验素材、拟生成素材及缺口。金融、保险等时效性主张核对当前权威来源。真实产品、数字、界面和业务结果优先使用真实材料，生成画面不得充当事实证据。

## 2. 写出整片脚本与镜头计划

先确定开头、论证或故事推进、结尾及声音承载方式，再拆镜头。保留已确认表达，不因视觉方案擅自改观点。脚本至少包含实际口播或字幕、画面功能与预计时长；无旁白作品也要明确观众从画面和文字获得什么。

每个镜头记录：

| 字段 | 要回答的问题 |
|---|---|
| 镜头与时间 | 这一段位于哪里，持续多久？ |
| 语句或事件 | 观众此时听到、读到或看到什么？ |
| 表达目的 | 是证明、演示、解释关系、推进动作还是建立情绪？ |
| 观看重点与状态 | 观众此时看谁或什么？哪些内容需要变化或稳定阅读？ |
| 空间与观看位置 | 主体、环境与前后层如何组织？相机为何移动或保持稳定？ |
| 动作原因与响应 | 什么启动动作？哪些物体先后响应，如何落定？无需受力模拟时说明实际信息变化。 |
| 跨镜承接 | 通过对象、操作、声音、视点或语义怎样接到下一镜？明确切换是否更利于理解？ |
| 素材路线 | 用代码、生成片段、实拍、图片或录屏，理由是什么？ |
| 画面与声音 | 主体、动作、关键文字、转场、声音落点是什么？ |
| 验收依据 | 什么实际画面或声音能证明本镜头达标？ |

一镜头保留清晰的视觉重点。需要动作表达时写可观察的变化，例如“放下物件→被拿走→收到现金→柜台变空”，不能用抽象词代替行为。标题、列表或图表有明确任务时正常使用，并留够阅读时间，不要求每镜复制同一布局或持续移动。需要人物一致性时先确定参考资产和使用边界。

## 3. 用代表段检验导演方案，再做完整预演

先读 [motion-direction.md](motion-direction.md)，根据实际音轨、台词或无声阅读建立事件节奏。选最能暴露风格问题的一段，包含主体动作、一次响应或跨镜承接，而不只做标题入场。静态早/中/晚构图用于排除遮挡与信息量问题；随即做真实可播放动作，检查运动中间态、惯性、关注点和镜头切换。静态通过不等于镜头方案通过。

代表段成立后用真实 HyperFrames 或已有 Remotion 工程渲染覆盖全片的动画粗稿。粗稿包含实际时间轴、主体承接和可检查的声音或字幕，是可播放MP4；未完成资产可以简化形状，但不能用全屏卡片序列替代需要检验的动作。按 [motion-quality.md](motion-quality.md) 记录实际观看范围、成立的表达和需重做的问题。已有连续执行授权时继续独立制作，不因外部文章建议添加固定等待门。

声音按实际接入能力处理：用户录音可直接成为正式声音来源；正式配音须有用户选定或已确认的声音及可执行适配器；本地 Huihui 等试音只用于预演，声音性质记在交付文件，不能上屏制作标签。正式配音未就绪时保留这个缺口，不把试音静默转为正式交付。用户要求无声时不添加BGM、TTS或假定BPM。

检查全片内容是否成立、时长是否够读、画面是否支撑表达、声音是否自然。先解决这些问题，再投入高成本生成或复杂动效。锁定进入制作的脚本与预演版本；后续改词或换声音时重新核对受影响的时长与镜头。

无真实 A-roll 的新创作沿用本地独立工程：保留实际预演/成片、工程、哈希、素材来源和审片反馈，不调用核心 `ingest --role a-roll` 冒作原片。已有适用的核心项目时才按真实合同登记素材、分镜与版本；接口限制见 [runtime.md](runtime.md)，不手改状态绕过。

## 4. 按镜头制作实际资产

先按[素材库](material-library.md)找已有文件或正常可下载的实拍/资料，用[中文片段检索](material-semantic.md)查本地库。候选实际审查后选源区间，不将搜索结果直接当已采用；缺口再选择图片、代码或必要生成。来源、许可与选段sidecar一起留在工程。

| 路线 | 适合承担的工作 | 执行与验收要求 |
|---|---|---|
| 代码动效 | 主体动作、空间关系、资金/物体交接、时间、精确数字与机制 | 实现动作原因、状态变化、选定的空间与跨镜承接；主次对象可以错开启动和落定。检查真实运动中间态、阅读与时间轴，交付工程源文件。 |
| 生成视频或图片 | 无法取得的场景、有必要的具体人物动作或氛围 | 图片优先内置工具；MiniMax默认只用于极少数有明确动作或叙事价值的镜头，一张图可表达同样内容时不付费生成视频。执行仍须满足预算、镜头批准和核心合同，保存有效请求与回执并查看结果。精确文字和数字后期排版。 |
| 既有素材 | 真人表达、事实证据、产品、真实界面、操作结果 | 检查原素材及使用范围，裁切和节奏服务当前镜头；保存来源和引用区间，避免改变原意。 |

内置 `image_gen` 是默认图片生成入口，实际控制项以本次工具接口为准。有连续对象、空间与响应的代码镜头优先使用 [directed-runtime.md](directed-runtime.md) 的场景描述，或手写实际HTML/Remotion工程；核对支持的节点、运动近似和相机范围。基础 `build-composition.mjs` 保留用于已有媒体、音轨和字幕的拼接，卡片不作为默认完整镜头。已有 Remotion 工程按已验证运行方式接续；选型服从表达和交付要求，不把所有镜头强制改写为同一种技术。

需要来源参考时读取 [motion-library.md](motion-library.md)，按职责检索包内案例索引。标题、清单、对照、数据等局部辅助可由 [motion-components.md](motion-components.md) 构建；不能把八种组件轮播视为默认导演方案。先检查运动中间态、结果帧和乱序seek，再导出接入整片。有旁白或要同时交付横竖版时使用 [voice-and-timing.md](voice-and-timing.md)，让实际声音决定镜头长度，并分别重排构图。

有来源的时间趋势数据可按 [data-charts.md](data-charts.md) 使用本地 LiveCanvas 入口导出折线动效。原生3:4、3秒的结果适合作为片中素材；需要不同画幅或较长阅读时间时调整母工程布局与结果停留，不拉伸图形或冒充可变时长模板。

生成视频只有在真实连接、有效模型、执行授权、预算与项目合同均满足时才能调用。MiniMax 状态查实时配置与本项目回执；用户禁用时不调用，自动付费默认关闭。插件说明存在不证明执行工具可用。正式旁白采用已选择的本地本人声音路线，按 [personal-voice.md](personal-voice.md) 核对样本和运行器，不替换成默认系统声；缺口不阻碍独立镜头制作。

## 5. 组装整片并审查声音与画面

以锁定版本组装所有镜头、旁白、字幕、音乐和音效，指定一个字幕 owner 与一个最终音轨 owner；外部组件不各自烧录第二套字幕或旁白。落点依据实际音频及输出时间轴，改写后不能直接继承旧 ASR。缺少修改稿对齐能力时人工核对，不宣称已经强制对齐。

统一全片构图、颜色、字体和节奏，但允许不同镜头承担不同功能。参考作品只用于提炼局部方法；不把某个案例的固定切镜频率、音效密度或结尾形式设为所有视频的规则。

实际导出后按 [验收说明](acceptance.md) 检查首尾、转场、字体、遮挡、生成缺陷、内容与画面一致性。播放并听实际声音，检查人声、音乐和音效的相互关系；没有可用听审能力时记录未听审并提供可播放音轨，不能把音频指标当主观试听。文件存在或渲染完成不能代替审片。项目要求尾帧冻结时，核对整幅成片画面和声音的实际行为。

## 6. 交付、修订与能力边界

交付可播放的完整 MP4、可继续修改的实际工程源码、素材清单，以及 QA/审片记录。清单区分用户素材、外部来源、生成素材与授权范围；记录成片参数、文件哈希、查看过的关键帧、实际播放/试听范围、缺陷和修订结果。工程源码按真实技术交付，HTML/TSX 工程不能称为原生 AEP。

遵循项目已有审片流程：初稿供用户确认，依据反馈修订并独立复核，再交付第二稿；只有用户明确确认才能标记定稿和按授权归档。记录“已生成、已运行、已审片、用户确认”各自证据，不把目录名或技术检查当作最终确认。

这条路线由 Agent 串联本地制作。当前核心尚未提供无 A-roll 的完整编排，代码创作可独立生成 MP4、源码、资产和审片证据；本人 TTS 与生成视频以实时配置、执行回执及实际试听核实。持续完成已授权且可执行的工作，不把独立渲染称为核心状态已推进或用户已定稿。
