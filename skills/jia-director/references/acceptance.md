# 最终文件与审片

当前制作须先执行[王杰已采用的花叔13项规则](huashu-rules.md)及其明确适用范围；本文保留的旧方法、组件或历史案例不是豁免。新方向三构图选择为人工节点，流程图标红；已确认方向的常规修订不重复选型。

## 每次交付前

1. 对最终 MP4 运行 ffprobe 和解码检查，核对时长、画幅、帧率、画面/音轨、字幕范围、缺失素材与尾帧；源码通过后端 lint/布局检查不等于最终文件通过。
2. 从最终文件解码开头、镜头切点前后、信息最密的帧、主动作的早/中/末状态和结尾，检查中文、数字、证据、人物/字幕避让、阅读时间、越界与突帧。只检查抽样帧时说明范围。代码动效按 [motion-quality.md](motion-quality.md) 再检查主体、空间、运动原因、跨镜承接和重复整页结构。
3. 实际回听原声/旁白连续性、剪口、停顿、音乐与音效的相对音量、爆音和末句是否完整。没有可用的听审能力时写明未听审，输出可播放音轨供用户检查；不能把 RMS、峰值或 ASR 校验称作主观听审。
4. 逐段核对讲述：删除是否改变观点/因果/限定条件，精剪是否保留反应和自然停顿，补图是否解释信息、支持事实、且在正确台词出现。金融/保险等时效性事实使用当前权威来源；素材不能伪装成真实证据。
5. 实际检查视频里没有AI示意、初稿、样片等制作状态标签，包括图片或旧素材已有文字。构建器文本门禁不能检查嵌入图像。版本/来源/审核状态放交付文件，合同条件与单位等正文仍需正常可读。
6. 记录最终文件 SHA256、实际运行命令、原输入/素材版本、技术及创作审查范围、问题与修复。报告可以保存为 `qa/技术检查.json` 与 `review/审片-v01.md`；它们是证据，不另建项目状态。技术PASS不能代替“是否像PPT”的判断，也不能代替用户确认。

原片任务另回读粗剪视频、精剪底片、删改说明、粗剪→精剪映射与字幕审校范围；补图不能掩盖缺失的粗剪/精剪阶段。本人配音需写明真实参考样本、实际本地合成回执与本人试听状态；本地 runtime verified 或系统试音不等于本人正式声音通过。合成检查唯一字幕轨与唯一原声音源，避免重复字幕和叠声。

原创动画与生图辅助镜头还须分别记录动作表现、背景美术及实际连续观看的覆盖与结果（PASS / FAIL / PENDING / 有理由的NOT_APPLICABLE）。动作审查核相位、中间态、重心、接触和循环；背景审查核完整构图、材质统一、空间与主体关系。未看或仅复验局部穿帮时，未覆盖项保留待审，不能合称“整片创作审核通过”。既有机器合同并不自动判断这些美术项目，不虚构自动评分或新增程序门禁。

自动收集最终文件证据可用 [media-inspection.md](media-inspection.md) 的本包脚本。新增或改写动效还应在浏览器中等待字体/图片加载，比较顺序播放与乱序 seek 的同一时刻画面；对渲染后的切点前后逐帧回查。只通过源码 lint 不能宣称这两项已检查。

## 对应用户节奏

- 用户只要粗剪：交付粗剪、可编辑删段决策、字幕与时间码映射、语义问题，不自动精剪或付费补镜头。
- 用户要完整制作：已授权的本地阶段连续执行；新风格/高成本生成确需方向确认时提供代表段，不强制所有局部步骤都确认一次。
- 初稿记录为待用户确认；承接反馈并保留修改对照，独立审片后给第二稿；用户明确确认才记录定稿。核心 CLI 的 user authority 不可由 Agent 自己填写以跳过确认。

## 归档包

沿用 `E:\视频文档\YYYY-MM-DD_项目名`。最低保留原始来源或其可核验位置、实际使用的复制素材及来源/哈希、脚本与分镜、可编辑工程、全部交付版本、QA与反馈证据、运行说明。使用核心 `archive` 接口时先读 [runtime.md](runtime.md) 的输入与状态要求，不能靠目录存在宣布归档成功。

不能承诺本轮没有验证的交付格式：HTML/Remotion 源码可编辑不等于原生剪映草稿或 AE AEP；需要这些格式时验证对应真实工程入口并回读打开结果。发布、平台上传与成片定稿是不同动作，分别报告。

## 多 Agent 交接的补充

需要独立验证或新动作试片时，按 [执行与审核](execution-review.md) 固定源码/MP4 版本及覆盖范围，保留具体问题→修改→复验。执行者自检、审核者看片和王杰确认不能相互替代。
