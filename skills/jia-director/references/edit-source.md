# 口播剪辑路线：原片 → 粗剪 → 精剪 → 补图/动效

用于对已有口播、访谈、录屏或其他连续原片进行剪辑。严格依次确定内容取舍、内容节奏，再补充视觉。可以提前盘点素材与可用工具，但不要在精剪内容节奏明确前生成或铺入补图、B-roll 和动效。

用户只要求粗剪、接续已锁定粗剪做精剪、局部修改或审片时，执行对应范围，并核实前序产物。实际工具、配置、合同、导入与渲染接口见 [运行说明](runtime.md)。

## 1. 看原片，建立可追溯输入

读取项目约定和配置，检查真实工具能力。保留原文件，记录路径、哈希、时长、分辨率、帧率、声道及已有字幕；继承项目规格和版本规则。新项目按既有归档规则建立独立目录，不覆盖原片或旧版本。

实际观看并听原片，理解人物关系、表达目的、场景和原有节奏。转写是定位与审校材料，不能代替看片。使用已接入 ASR 时遵循运行说明中的路径及导入要求；核对姓名、数字、否定词、条件、因果、口误和重录，保留不确定项。

建立原片时间区间与转写之间的索引。标出不可改变的事实、已确认表述、必须保留的表情与反应，以及用户指定的片段。金融、保险等事实疑点要查证或列为待修正，剪接不能把限定条件剪掉后制造更强结论。

需要交换口水词/重说候选或补充口播动效方法时，按 [talkcraft-adapter.md](talkcraft-adapter.md) 使用原创词表/EDL 桥。它保留 ASR 原始词文本与真实文件散列，不把校对后的句子制造为准确词级时间；上游候选不能替代本通路的粗剪审批与精剪。

## 2. 粗剪：先决定讲什么、以什么顺序讲

粗剪完成语义取舍：删除明显错录、重复表达、拍摄指令及无效等待，整理必要的句序。保留主语、连接词、限定条件、因果链、自然反问与有表达作用的停顿；语义审校不能退化为仅删静音。

逐个剪点记录原片起止时间、保留或删除原因、粗剪输出区间。调整句序时说明叙述是否仍忠于原意；不可把相邻碎句拼出原片没有的判断。对争议区间先回听确认，不能只凭 ASR 文本自动删除。

本机优先使用 [本地审片面板](rough-review.md) 做原片顺序不变的粗剪：Skill 创建工程、结合实际原话和参考脚本生成有理由的保守建议，打开浏览器供逐词选择、恢复、检查呼吸及字幕。长间隔只是候选，不自动应用；语义建议由当前 Agent 生成，面板不包含独立 LLM 服务。改文字和删除录音分别记录。跨句改序仍需已有编辑工程，不把本面板称为支持任意重排。

导出并实际播放粗剪版本，检查完整论点、人物关系、连接处、尾音和口型。交付粗剪视频及删改清单，明确保留了什么、删了什么、改变了哪些顺序。这一阶段可以有便于审校的基础字幕，不以特效数量或成片感判断是否完成。

按用户的逐步模式或已有合同门禁确认粗剪；用户已授权连续执行时完成必要验证后继续。保存进入精剪的具体版本和时间映射，避免精剪使用尚在变化的粗剪。

面板导出的 `fine-cut.handoff.json` 冻结粗剪、SRT 与原片→粗剪映射的路径和散列；它承接本地精剪，不写既有核心状态。已有正式项目仍沿用核心 CLI 的校对、计划、路由、版本与确认，不把词级删除伪造为整句 operation，也不把“保存”代签为用户确认。

## 3. 精剪：先确定内容节奏与剪接质量

在已确定的内容上调整呼吸、间隔、强调、人物反应、问答承接与镜头连续性。检查切点是否截断词语、失去必要上下文或造成突兀表情；不要用统一加速、频繁放大或铺特效替代节奏判断。

保留原声作为口播基准。未经授权不替换人物声音；对音频切点、降噪和音量的调整以实际试听为依据。核对字幕文字及时间，正式视觉样式与动效放在下一阶段。

实际导出精剪底片并观看、试听。此时应能够仅凭原片内容看懂核心表达，内容和节奏已经成立。记录原片→粗剪→精剪的时间映射与仍需解决的问题；确定进入补图/动效的精剪版本。

帧级技术切点可使用 [fine-cut.md](fine-cut.md) 的原创本地 `fine-cut.mjs plan/render`：从真实有声 CFR 粗剪生成带源哈希的计划，核实切点后按实际计划文件 SHA-256 执行，保留原声并输出精剪 MP4、SRT、映射和 QA。它不处理新的语义删改/句序、不自动批准核心版本，不以一次摘要传入冒充实际回听。

独立本地审片工程可在 [review-stages.md](review-stages.md) 的第 02 步直接调整和回听切点。第 03 步读取真实精剪、按台词安排图片与代码动效，复用既有工具制作、登记和合成。两步使用固定上游版本与同一帧时钟；旧版下游不会被上游新修改自动覆盖。

ASR token 时间是辅助定位证据，不等同中文逐词准确度，也不是改稿后的强制对齐。采用精剪输出时间和实际声音重新定位字词落点；未经复核，不把原片时间码或其他 Agent 建议直接用于成片动画。

## 4. 补图/动效：为已明确的表达服务

精剪成立后按[素材库](material-library.md)及[片段检索](material-semantic.md)查已有实拍与资料，核对动作、上下文和授权，截出明确源区间再经`visual-asset-import`导入。索引和取材不改变精剪主时钟、原声或字幕，不自动采用Top1；现成素材不够再用图片或动效。

先为每个候选补充镜头写清功能，再选素材路线：

| 需要传达的内容 | 优先方案 |
|---|---|
| 人物的判断、关系、反应与可信感 | 保留可看的真人画面，必要时做局部强调。 |
| 产品、报告、数据、真实结果或操作 | 用户或官方可核验素材、真实截图与录屏。 |
| 时间、关系、选择、流程与因果 | 可修改的代码图形、文字与结构动效。 |
| 无法实拍的氛围或语义隐喻 | 已接入且获授权的生成素材，生成性质记录在素材清单，不上屏制作标签。 |

补充镜头计划记录精剪输出区间、原句或事件、表达功能、素材来源、关键文字、声音落点及验收方法。解释动效另写主体的起态、可见动作、落态和接回真人的办法，按 [motion-direction.md](motion-direction.md) 选择空间、响应与镜头；不把所有口播强制做成物理动画。静态布局只排除遮挡，再检查真实动作中间态与播放。具体时长服从原声与可读性，不固定要求每几秒切一次。

尊重原片硬字幕、脸部、关键界面和内容安全区。透明叠加、局部承载层、A-roll 小窗或全屏替换是可选择的构图办法；某个历史案例的做法不自动适用于所有视频。只有补充画面确实帮助理解时才加入。

按 [motion-library.md](motion-library.md) 为锁定精剪选择动作。有对象变化、空间与因果的解释插入，使用 [directed-runtime.md](directed-runtime.md) 或定制工程；按 [motion-quality.md](motion-quality.md) 审查动作是否帮助理解。流程、对比、清单等 [motion-components.md](motion-components.md) 组件保留为局部辅助，不用轮播它们取代整段真人表达。`lower-third` 的透明HTML层应合入真人合成工程，普通H.264导出不会保留透明。用精剪输出时间安排触发，不直接套用原片ASR时间。

口播涉及时间趋势且数据已核实时，可按 [data-charts.md](data-charts.md) 导出 LiveCanvas 折线镜头，接入精剪输出时间。保持数据来源和缺失值说明可读，按原片画幅重新构图，不裁掉图表刻度或来源。

图片生成默认使用实际可用的内置 `image_gen`；代码动效由当前可执行工程渲染。本通路排除 ChatCut。生成视频须同时满足工具连接、模型、执行授权、预算和项目合同，不能绕过尚未接入的适配器；本地审片面板不调用 MiniMax。历史服务成功记录仅证明当时案例，实际接口以运行说明和本次发现为准。

## 5. 合成与逐段审片

将素材放入锁定精剪时间轴，核对字词、动画、声音和剪点。一个字幕 owner 统一校对文本与时间，一个音轨 owner 统一原声、音乐和音效；组件不再烧录第二套字幕或叠播原声。精确数字、汉字、品牌文字用可控排版；生成素材中的文字不作为事实源。

导出实际 MP4，按 [验收说明](acceptance.md) 逐段检查口播连续性、字幕可读性、画面遮挡、叠加边缘、转场、尾帧、音乐与音效。用最终文件解码关键帧；播放并听实际成片，记录检查范围和发现的问题。没有可用听审能力时明确记录未听审并提供可播放音轨，不能把音频指标当主观试听。技术参数通过与用户认可效果分别记证据。

补图暴露内容或节奏问题时回到相应前序阶段修改。内容、声音或句序改变后重新建立受影响的时间映射，复核字幕和视觉落点，再导出新版本；不能沿用旧文件的哈希和审片通过记录。

## 6. 交付与状态

完整任务交付可播放成片、实际可编辑工程、素材清单和 QA/审片记录。保留原片、粗剪、精剪底片、各次导出及删改/时间映射，便于回看和修订。素材清单包含来源、使用区间、生成性质及授权范围；审片记录包含成片参数、哈希、关键帧、实际播放/试听范围和修正结论。

按项目已有流程交付初稿，收集用户反馈后修订并做独立复核，再交付第二稿。用户明确确认后才能标记定稿和按授权归档；仅完成粗剪时就标明粗剪交付，不把粗剪输出称为精剪或最终成片。

运行说明中已验证的能力可以直接用于对应步骤，尚未接入的能力保留明确缺口并推进独立工作。不得虚构 CLI、假装插件工具可用、把工程标签当生成完成，或把代码工程称为原生 AEP。每一步都用实际文件和审片证据承接下一步。
