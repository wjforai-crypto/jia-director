# 用镜头和动作组织视频

用于无口播制作路线的代码/混合创作，以及口播剪辑路线精剪稳定后新增的解释镜头。先承接用户用途、锁定事实与已有设计，不把导演判断退化为选择某个动画模板。

## 从一个事件出发

先回答：观众此时看什么；什么信息需要变化、演示或稳定阅读；之后应理解哪一点。为物体、场景和文字各安排职责。按H08使用一个具体例子贯穿，前3秒具体事件开场、以结果动作收尾；每镜可出现承担不同职责的对象，不要求同一个角色占满所有镜头。

分镜至少写清主体起态、主动作和落态。根据本镜头需要再补层级、力、相机、光或声音；无需每镜填满所有特效字段：

| 判断 | 制作时记录什么 |
|---|---|
| 观看重点 | 主体/次要对象，观众何时看向哪里；文字是否只命名或限定 |
| 空间 | 前后关系、遮挡、尺度；需要时区分前景/事件层/远景 |
| 主动作 | 可见的触发、动作轨迹、接触或变化点、结果 |
| 次级响应 | 谁被带动、延迟多久、幅度为何更小 |
| 相机 | 固定、跟随、推近、拉开、局部揭示的原因及落点 |
| 接力 | 上一镜的哪个物体、方向、颜色或运动接到下一镜 |
| 时间 | 实际台词/阅读/事件锚点，动作与留字区间 |
| 验收 | 同镜起态、中段和落态应各看见什么；跨镜如何衔接 |

避免默认“固定顶部标题＋中心示意图＋换下一页”。按H08先让具体事件建立问题，标题仅作画内必要命名，随后把注意力交给发生变化的主体。图表、文字对照和静稳镜头有明确说明职责时保留；用户要求演示页本身时按该范围执行。

## 五类制作判断，按镜头选择

**空间与错落。** 分层不是给同一张海报分几个DOM。近远对象有不同的尺度、遮挡或相机响应；启动时刻由动作关系决定。主体先变化，依赖它的对象稍后响应，相机必要时滞后跟随。一个主播放时间可以控制全片，但各层必须有各自的起止和曲线，不能全都套同一个0→1进度。

**动作准备、接触与落定。** 需要力度的主动作安排准备、加速、接触、形变及余韵；安静的动作可只保留其中合适部分。不能所有文字都撞击、所有东西都回弹。持续移动的对象跨状态/镜头要接住位置、方向与适当的速度；需要停住时让停住发生在可解释的减速或接触之后。

**可解释的运动。** 落下可用重力近似，惯性滑动可随阻尼减速，弹性表面可用可调阻尼响应。物理参数与位移/速度/受力关联，不用随机抖动代替。流程、数据和时间进度则可以线性，不能因追求弹性扭曲数值。注明哪些是视觉近似，哪些实际采用了模拟；不把GSAP缓动名称称为物理引擎。

**光与响应范围。** 设计中固定主光方向，让阴影、高光和局部反应一致。只在能说明环境被动作带动时加入接收面、局部光、拖尾或近远响应。远处反应更轻、更迟；不要默认全画幅震动。环境不必持续漂移，镜头内的细微生命感与最终稳定阅读并不冲突。

**节奏。** 有实际音乐时记录真实BPM/拍点，重要接触或转折对齐选定落点，准备和余韵留呼吸；有旁白时先服从语义与实际字词时间。无声片用事件先后和阅读时间建立节奏，禁止自动补音乐或伪造已检测BPM。声音授权、正式音色和接入限制继续见 [voice-and-timing.md](voice-and-timing.md)。

## 先验证代表段，再扩到整片

在昂贵或长时渲染前，挑一段最能暴露空间、主动作和转场的问题，做可播放的短段及起/中/末三态。静态关键帧检查构图只是其中一项，不能把几张板式稿当成动画预演。查看对象运动和镜头如何呼应，然后再推广全片。

向用户呈现代表段是为了让方向可审查。新角色/风格按已采用H07先做三构图选择；已有选定方向和连续授权内继续独立工作，不为每个工具另设审批。事实或成本会实质改变任务且无法推断时才提问。

## 寿险案例应怎样改变

上一版的逻辑可读，但大多数构图停留在固定图标＋线路＋短标题。新镜头要把保留的事实改写成一段能看见的事件：收入物体移动并带动生活责任，来源停止而责任继续，合同条件开启后给付到身故受益人，有限资金被分配给仍在延续的生活。

观众的视点可以跟随其中一个物体走向正在显露的责任，再靠同一位置/运动转到合同和给付；不是每一条句子独立换一页。已经身故的收入主体保持退出，结尾交给继续生活的人。真实保单条件、受益人主体及“分担压力”不能因镜头隐喻丢失；不得暗示无限收入恢复或全部责任清零。

## 执行与边界

导演方法不等于圆球、合同门和人物符号组成的新模板库。包内16秒示例检验运动能力，不能机械换文案作为所有项目的风格。机制解释可以使用可读的示意空间；要表达温暖、失去或生活继续，另外设计具体生活场景、人物行为和环境变化，需要时使用本地自绘SVG/图片等资产或定制工程。不要让整个故事停留在同一张宽景关系图上，再把局部运动当作全部创作工作。

少量分层、相机和确定性运动可用 [directed-runtime.md](directed-runtime.md) 的本地执行层；其能力以实际schema及验证结果为准。可手写当前后端支持的HTML/SVG/Canvas/Remotion镜头，必要时使用本宿主已启用的GSAP、ShotCraft、Three等能力，不能仅列工具名字就称已实现。

原 [motion-components.md](motion-components.md) 的八个组件是局部辅助和兼容实现；照片轻推、标题出现、卡片清单并不自动构成上述镜头叙事。LiveCanvas只在真实数据叙事合适时使用。MiniMax只选极少数有明显表达价值的镜头，单图等价时不生成付费视频。

实际复核方法见 [motion-quality.md](motion-quality.md)。可seek与可重复渲染是执行要求，不是艺术质量证明；不要再用一次技术PASS结束创作审查。
