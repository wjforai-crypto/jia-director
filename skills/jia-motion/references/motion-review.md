# 动作验收：先看事情是否发生

一次检查只针对本片实际风险。修复后复查受影响部分，不为凑条目要求每镜相机移动、同一主体、物理受力或不停运动。

| 检查 | 观察与证据 | 不通过时回到哪里 |
|---|---|---|
| 姿态与动作覆盖 | 连看实际循环/过渡，检查预备、执行、接触、落态与重心；输出fps与姿态更新节奏分列 | 动作资产、关节/形变与时序，不能只增加导出fps |
| 背景与场景美术 | 主体与完整背景同屏，材质/色板、光影、地面和遮挡相容；需要空间时有有效景深/视差 | 背景资产与场景设计，不能只以纸纹或横移代替 |
| 主体行动 | 去掉装饰，能否读到明确的变化/操作/反应；将主体与相机/特效时钟分开检查 | 动作脚本与主体状态 |
| 连续形变 | 同一身份；中途改目标位置不跳，必要时速度也承接；内容错开且不挤叠 | 状态函数、布局与内容时序 |
| 跨镜 | 看接缝前后邻帧；追踪承接物的屏幕位置、尺寸、方向与速度 | 接缝与相机路径 |
| 结果与阅读 | 结束动作有明确结果；信息有足够时间被看清 | 分镜时长与注意力安排 |
| 运行可重复 | 顺序、倒序、跳转后重复同一时间，真实截图一致；字体、图片加载完成 | 时间求值与资源加载 |
| 速度与模糊 | 实际连看高速运动；需要时同镜比较帧率/子帧，避免跨硬切混帧 | 输出参数与快门实现 |

文件帧率、每帧都不同、切镜数量、自评8分都不能单独证明动作质量。颗粒会让定格主体也有逐帧差异。冻结可以是导演选择，但需明确用途，不能大面积冻结主体后以机位数量冒充事件数量。

`scripts/inspect-motion.mjs`只验证本包时间入口、资源/浏览器错误、重复seek截图、DOM身份与取样，不自动判断审美。检查源码预览后，还要从最终MP4取样和连续看；有声音必须另听审，未听不报通过。

机器报告保存`technicalVerified`与`userAccepted`两种状态。本人确认具体版本后才进入已确认配方；局部通过不代替整片验收。


## 源码参考项目的物体交接

对拿取/放下/变形/释放，追踪同一ID的所属关系、可见数量、实际屏幕位置与前后层；先看高风险短段，再看最终MP4邻帧。状态确定、帧数正确和描边有颗粒，都不能证明物体没有瞬移。源码运行器可读复用绘制计算的状态探针；未接探针记为NOT_INSTRUMENTED。方法、阈值与命令见[source-backed.md](source-backed.md)。

## 独立审核与返修

按 [执行与独立审核](execution-review.md) 固定提交版本、帧号和证据。文件 fps、角色动作采样、纹理节奏及播放掉帧分别判断；审核者实际看过的连续区间和未覆盖项分别记录。试片只证明对应能力，不代替整片节奏与用户确认。
