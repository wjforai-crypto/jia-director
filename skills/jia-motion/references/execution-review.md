# 执行、独立审核与返修

当前制作须先执行[王杰已采用的花叔13项规则](huashu-rules.md)及其明确适用范围；本文保留的旧方法、组件或历史案例不是豁免。新方向三构图选择为人工节点，流程图标红；已确认方向的常规修订不重复选型。

适用于新后端、新动作能力、参考复刻或多 Agent 执行后需独立验收的项目。沿用当前工程和授权；这是一份交接约定，不另建项目状态机，也不要求每镜加审批。

## 谁做什么

| 责任 | 实际产物 | 边界 |
|---|---|---|
| 执行者 | 读任务与源码、准备角色/场景、实现、渲染、自检、保留失败日志和修改记录 | 不改审核阈值来迁就输出，不代签独立审核或王杰确认 |
| 审核者 | 核对提交版本与文件、复跑必要检查、观看动作与接缝、给出具体返修并复验 | 不能把加载 Skill、文件存在或技术 PASS 当效果成立 |
| 王杰 | 已有授权外的方向/内容取舍、新音色和最终审美/定稿 | 已定方向内常规纠错由 AI 推进；发布另按授权 |

由一个执行者拥有本轮项目源码，审核证据写入新的 review/qa 批次。审核者要直接修改源码时先交接编辑权并固定新版本，避免双方同时写同一工程。Skill 变更走本机中央治理，不把执行项目里的经验文件直接安装成 Skill。

## 先让高风险短段过关

新能力或已失败的动作先挑 5–8 秒代表段，优先覆盖接触、抓取、释放、形变、遮挡、角色表演或高速运动。时长可因实际事件调整；不要挑一段容易的字幕卡代替待验证能力。保留用户认可的原画面和有效原栈，在独立副本改；固定同一角色、场景、材质、声音安排和时间域，避免一次换掉所有变量。

任务可直接写在原 brief/分镜里，最少补齐：

- **可复用资产**：角色比例/轮廓、关节与接触点、表情与身体动作、场景地平面与遮挡、色板/字体。已有源码中的有效定义直接引用，不强制重画角色卡。
- **可见事件**：每个角色在做什么、为何行动、准备→主动作→落态、观众视线与结果；文字/相机/粒子不能代替主体表演。
- **对象和交接**：同一 ID、拥有者、可见数量、接触点、实际屏幕坐标与层级；切换前后谁承接、是否应保持速度。世界坐标/屏幕坐标注明空间。
- **实现分工**：绘制层、时间编排/合成层、导出层分别采用什么。Canvas/p5/WebGL/Three 与 Remotion/HyperFrames 可组合，始终只有一个主时钟和最终输出 owner；不强制换栈。
- **时间与规格**：输出 fps、角色/线条/粒子更新节奏、必要子帧采样分别写清。输出时间到源码时间用 offset/rate 显式映射，区间用 [start,end)，第 n 帧为 n/fps。
- **检查点**：列出最危险的动作时刻和预期可见结果，含接触/释放前后邻帧。固定姿势或低频线条抖动有意为之时说明范围，不能笼统冻结主体。

30/60fps 指真实输出采样。像素角色可按 10fps 换姿势、粒子按 60fps 更新；这是有意设计。把 10/20fps 视频补帧复制成 60fps，不算重新计算了动作。反过来，60fps 文件也不证明表演流畅。帧间像素变化可能只来自颗粒，播放掉帧又是第三种问题。只有高速运动确实需要时才比较子帧/快门，不能拿模糊掩盖坐标跳变。

## 生图服务动态镜头

仅在本镜确实使用生成图片时加载本节；生图是可用的资产方法，不等于另换导演路线。沿用当前授权和宿主图像入口，不因本节重生已有可用资产。

生图前在原brief/分镜补一段制作判断：

- **动作与资产覆盖**：逐角色列起态、预备、执行、接触/释放、落态与循环接缝。为这些变化选择连续姿态序列、分层关节/网格变形或混合方法，注明每种资产承担的动作；图片数量从动作需要推导，不能先定四格再压缩剧情。涉及抓取或递接，画清手/口与道具接触点及道具由谁绘制，避免多生成一份道具。
- **动态节奏**：分别说明输出fps、姿态序列的实际更新节奏及代码连续求值部分。自然跑动若只有两姿势往返且不符合目标，就补蹬地、腾空、落地等相位或分层运动；可先试8–12姿势的循环，但这是可调整的试验起点，不是每种动作的统一数量。风格允许的像素、定格或低频笔触保留；增加文件fps、颗粒、镜头平移或模糊不能冒充主体动作增加。
- **可动画性**：保持同一身份、体型、服装、视角与尺度；姿态间检查轮廓、中间态、支点、速度和重心，不只对齐手上的道具。分层方法留出关节覆盖和运动空间，图集分辨率满足主体在最终画面的实际尺寸，避免把过多小格放大交付。
- **背景与美术**：先在成片同一工程中看人物与完整背景。按本镜用途检查前后景、地面透视、材质、色板、光照/投影和遮挡；精细照片人物不能因省事搭配明显不协调的简陋矢量背景。简约或矢量可以成立，不强迫所有场景生图、分固定层数或持续运动。
- **动态验证**：代表段覆盖真正的风险动作，带最终使用的背景与相机正常速度播放，再查关键/中间姿态、接触与接缝邻帧。明确是哪项素材或动作需要补足后再生图，不以静帧漂亮、图集存在或编码30/60fps放行扩片。

审核在现有记录中分列技术、动作表现、背景美术、实际连续观看及本人接受；写实际覆盖和证据。只修穿帮时仅报告对应复验通过，其他项待审。机器脚本仍只验证其声明范围，不因增加这些文档字段就声称已有自动美术验收。需要用户决策时遵循原有代表段/审片节点，不新增逐张生图审批。

## 提交什么，检查什么

沿用现有 source-check/source-render 或原生命令；已有可靠渲染器不必为过审迁移。没有统一后端时，可用本包 inspect-export.mjs 的独立 spec 模式核验最终文件。提交至少包含：

1. 实际 MP4、固定可修改源码、资产/依赖与运行命令；记录提交源码范围和 SHA256、MP4 SHA256、源码时间映射。参考原件只读保存，不能让渲染过程悄悄改变配置。
2. 本轮真实运行记录：执行时间、命令参数、退出码、标准错误、失败/修复；所有编码子进程检查退出码和输出。README 的“完成”不能代替这些记录。
3. 从最终 MP4 解码的动作起/中/末、风险时刻邻帧与连续小片。顺序/倒序 seek 属于源工程测试，不冒充最终 MP4 动作审查。
4. 明确的检查覆盖和遗留问题。输出 fps/实读帧数/时间戳/全帧解码只属文件检查；角色表演、物体交接、连续观看、听审和本人认可分开记录。

`node scripts/inspect-export.mjs --spec <spec.json> --input <video.mp4> --output <不存在的report.json>`

spec 最小字段为 width/height/fps/duration；可选 audio 为 none/required/optional，frameMode 为 cfr。cfr 模式会逐帧核对时间戳间隔，但仍不能识别复制帧或评判主体动作。旧的 `--project <含scene.json的工程>` 用法保留。命令失败返回非零并尽量留下失败报告；不能覆盖已有报告。完整提交模板见 [review-contract.example.json](../assets/review-contract.example.json)。这是可选字段范本，不要求旧项目增加无关材料。

## 审核与返修闭环

审核结论绑定 **具体版本、MP4 哈希、源码清单哈希和覆盖区间**；有任一变化即复验受影响部分。文件检查、动作/视觉审查、声音检查、用户接受分别记录。每项使用 PASS / FAIL / PENDING / NOT_APPLICABLE；无探针明确记 NOT_INSTRUMENTED，并用实际画面补查，不能将空白默认成 PASS。

每条问题写：时间码和帧号（注明从 0 开始）→预期→实际→证据路径→修改方向→责任人→复验结果。阻断播放/规格不符/主体交接或锁定内容错误先修；再处理动作重量、遮挡、节奏与质感。工具静态检查只能发现其声明范围内的问题。

执行者修复后给新版本和对应新证据；审核者复看受影响动作及相邻承接。试片通过只放行同类实现向整片推进，整片节奏、素材、声音与王杰确认仍需分别检查。用户已经授权范围内的纠错继续做；只有效果/预算/锁定内容有实质冲突才带证据询问。

本约定来自已发现的交付缺口；流程和脚本可验证，不代表某种新动作已通过。至少在真实试片中完成一次提交→问题→修改→复验后，才将具体动作标为已验证；跨两个不同内容稳定复用后再提炼配方。
